A reader of untrusted JSON refuses a property named `__proto__`, `prototype` or `constructor` with a `DataError`, which the objects of valibot dropped unseen. `recordSchema`, and so `strictRecord`, `looseRecord` and every schema behind it, refuses them on the object it reads: a key of `compileScoring`, an item stage, a module resolution file, a declaration of a value and the settings of a support. `readCandidateAction` and `readResultsJson` refuse them at any depth through `checkJsonInput` of `@assesskit/runtime/checks`, which also checks their limit of size, and the content of a view refuses all three through `plainSchema`, which is now in `@assesskit/runtime/checks`. `mapSchema` keeps them as data, as the identifier of an option in `points` and a module id are.
